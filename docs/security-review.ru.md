# Vinaire — пакет для разбора безопасности

[English](./security-review.md) · **Русский**

Для тех, кто проверяет Vinaire или проводит пентест, прежде чем он станет доступен за пределами доверенной сети
(Roadmap, Phase 50). Сканеры (govulncheck, gosec, npm audit, gitleaks, Trivy, ZAP) уже в CI; *логических*
ошибок они не находят — неверную проверку прав, подмену личности, пропущенный шлюз. Этот документ показывает
человеку места, где такая ошибка важнее всего, говорит, что уже доказано тестами (чтобы не тратить время на это)
и что выходит за рамки.

Сначала прочтите [security.ru.md](./security.ru.md) (модель угроз, проверенные свойства, остаточные риски), затем
[AGENTS.md](../AGENTS.md) (правила, которым подчиняется любое изменение) и [api-routes.md](./api-routes.md)
(все HTTP-маршруты, генерируются из роутера).

## 1. Что такое Vinaire, в одном абзаце

Веб-интерфейс перед кластерами Kubernetes. Go-бэкенд (chi, client-go) отдаёт статический экспорт Next.js и
JSON/WebSocket API. Почти каждый вызов идёт **от имени вошедшего пользователя**: его токен Kubernetes (вставленный
токен ServiceAccount, короткий токен ServiceAccount, который Vinaire получил для человека, вошедшего через Keycloak, или — только если API-сервер доверяет issuer — ID-токен OIDC) хранится на сервере за непрозрачной HttpOnly-cookie сессии и используется
для вызова, так что решает RBAC кластера, а не Vinaire. Vinaire хранит учётные данные зарегистрированных кластеров
(запечатанными) и выполняет несколько действий с **собственной** личностью (информеры живых обновлений, собственные
настройки, фоновый GitOps).

## 2. Границы доверия

Схема — в [английской версии](./security-review.md#2-trust-boundaries). Недоверенное: браузер и всё, что он
шлёт; **все данные, прочитанные из кластеров** (имена, метки, строки логов — выводятся только как текст);
репозитории Helm, реестры и git; URL Keycloak, введённый в мастер. Доверенное (конфигурация оператора):
переменные окружения, значения чарта, адрес провайдера ключей.

## 3. Критичные пути — где тратить время

| Путь | Код | Что пытаться сломать | Что уже доказано |
|---|---|---|---|
| **Вход и сессии** | `internal/authn` | войти за другого; сохранить сессию после выхода/истечения/отзыва; фиксация; подбор; прочитать чужую сессию; спутать режимы токена и OIDC; переключение Keycloak на лету | энтропия и ротация id, флаги cookie, ограничитель, потолок 12 ч, общее хранилище без читаемых токена и id, отзыв доходит до всех реплик, вход по токену нельзя выключить без включённого OIDC |
| **Брокер идентичности (вход через Keycloak по ServiceAccount)** | `internal/oidcbroker`, `internal/authn/oidc.go`, шаблон чарта `users-namespace.yaml` | получить больше, чем у человека есть: переиспользовать чужой аккаунт, заставить Vinaire создать привязку или роль, выпустить токен вне пространства имён людей, прочитать Secret правами брокера | брокер создаёт только ServiceAccount и токены, привязок — никогда (`TestFirstSignInCreatesAnAccountWithNoRightsAndATokenForIt`); одноимённый чужой аккаунт не присваивается; Role чарта на настоящем кластере останавливается на своём пространстве имён (`integration/broker_test.go`); удаление аккаунта завершает его токены за секунды; http-Keycloak нельзя сочетать с режимом API-сервера. **Известное ограничение:** ключ — только OIDC-subject (issuer добавит Фаза 82 ROADMAP) |
| **Покрытие аутентификацией** | `backend/router.go` | найти маршрут, отвечающий без сессии | `TestEveryRouteNeedsASessionExceptTheSignInFlow` обходит роутер; шесть открытых маршрутов названы с причинами |
| **Права по пользователю** | `internal/api/*`, `internal/stream/authz.go` | прочитать или изменить то, что RBAC вызывающего запрещает; дойти до кластера личностью Vinaire вместо его | обработчики используют `rest.Config` вызывающего; живой поток фильтруется по каждому событию; тесты «токен вызывающего, не бэкенда» |
| **Exec / терминал** | `internal/stream/exec.go` | открыть оболочку без `pods/exec`; сохранить её после выхода; обойти проверку origin | начало **и** конец аудируются; проверка origin на каждом WebSocket (иначе тест ломает сборку) |
| **Показ Secret** | `internal/api/secrets.go` | прочитать значение мимо аудируемой ручки; пропустить аудит | значения только через `reveal`, от имени вызывающего, с аудитом; списки отдают только метаданные |
| **Применение YAML** | `internal/api/apply.go`, `internal/k8s/apply.go` | записать то, что вызывающему нельзя; применить два документа; протащить заглушку Secret; обойти dry-run/resourceVersion | ровно один документ, лимит размера, строгие поля, dry-run, 409 при устаревшем resourceVersion; `FuzzParseSingleManifest` |
| **SSH-установка** | `internal/provision`, `internal/api/provision.go` | добиться выполнения команды, которую пользователь не вводил; дойти до loopback/metadata; утечь учётные данные; обойти пин host key | строгие шаблоны + одинарные кавычки (`FuzzShQuote`, `FuzzProvisionValidators`), `ValidateTarget`, пин host key, редактирование `Secret`, canary-тест |
| **Реестр / хранение ключей** | `internal/clusters` | открыть хранилище без ключа; подменить или откатить его; найти учётные данные в логе или ответе | AES-256-GCM, ротация ключа, провайдер ключей (только обёрнутый ключ, fail-closed), canary-тест, `FuzzParseKubeconfig` |
| **Мастер Keycloak** | `internal/keycloak`, `internal/api/keycloak.go` | заставить Vinaire ходить по внутреннему адресу; запереть всех; прочитать секрет клиента или пароль администратора | защищённый клиент, шлюз `auth.vinaire.io`, незашифрованное хранилище отвергается, секреты не возвращаются, `FuzzParamsValidate` |
| **Установка Helm** | `internal/helm`, `internal/api/catalog.go` | поставить больше, чем позволяют права вызывающего; назвать репозиторий/URL в запросе; обойти проверку digest | `rest.Config` вызывающего, репозитории только из конфигурации, sha256, preflight |
| **GitOps (native)** | `internal/gitops` | применять от имени Vinaire вместо заданного ServiceAccount; утечь токены; читать вне пути источника | токен ServiceAccount на источник, запечатан, `netguard`, git в памяти |
| **Прокси проброса порта** | `internal/api/portforward.go` | дойти до пода, недоступного вызывающему; отдать cookie сессии поду; скрипт на origin Vinaire | личность вызывающего, CSP `sandbox`, cookie не пересылаются, `FuzzParseProxyTarget` |

## 4. Что проверяется автоматически (проверять повторно не нужно)

* **Каждый маршрут требует сессию**, кроме названных маршрутов входа; **каждый изменяющий маршрут ограничен по
  частоте**, кроме названных (`backend/router_test.go`); `docs/api-routes.md` перегенерируется из роутера, и
  тест падает, если он устарел.
* **Тело каждого запроса ограничено по размеру** (`TestEveryRequestBodyIsSizeLimited`).
* **Правила кодовой базы** (`backend/codebase_rules_test.go`): нет `InsecureIgnoreHostKey`, проверка TLS
  пропускается лишь в трёх проверенных местах, проверки origin у WebSocket и другое.
* **Фаззинг** (workflow Security, по 30 с на цель при каждом запуске; затравки — в каждой сборке): разбор
  kubeconfig, URL серверов кластеров, разбор токенов и ключей, YAML из одного документа, цели проброса,
  проверка меток/taints нод и привязок RBAC, shell-кавычки и валидаторы SSH-установки, параметры стека метрик
  (внедрение YAML), параметры Keycloak.
* **Canary-тест:** метка во всех полях с учётными данными не попадает ни в лог, ни в ответ об ошибке.
* **Цепочка поставок:** SBOM (CycloneDX) репозитория при каждом запуске и каждого выпущенного образа; образы
  подписываются cosign (keyless) с аттестацией происхождения (`.github/workflows/release.yml`); сторонние
  действия закреплены по коммиту.

## 5. Что *не* покрыто — посмотрите сюда

* **Авторизация делегирована Kubernetes.** Исправный Vinaire не поймёт, что ClusterRole слишком щедрая.
  Проверьте роли чарта (`charts/vinaire/templates/clusterrole.yaml`).
* **Браузерная сторона за пределами CSP/XSS-проверок:** ручной проход по выводу данных кластера без
  `dangerouslySetInnerHTML`, интеграции Monaco/xterm и отсутствие `postMessage`.
* **Гонки и логика между обработчиками:** создание и отзыв сессии; порядок переключения токен/OIDC;
  read-modify-write реестра; промежуток dry-run → запись при применении.
* **Отказ в обслуживании:** лимиты записи по личности есть; сторона чтения, число WebSocket и веер информеров
  ограничены, но нагрузочно не проверялись.
* **Окружение развёртывания:** ingress, TLS, применение NetworkPolicy со стороны CNI (политика рендерится и
  принимается, применение не проверялось), политика Vault/KMS, кто читает namespace Vinaire.

## 6. Как запустить всё самим

```bash
cd backend
go build ./... && go vet ./... && go test ./...                 # включая тесты роутера и правил
gosec -severity medium -confidence medium ./...
govulncheck ./...
go test ./internal/clusters -run '^$' -fuzz FuzzParseKubeconfig -fuzztime 2m   # любая цель Fuzz*
UPDATE_ROUTES=1 go test . -run TestRouteInventory                              # перегенерировать docs/api-routes.md
cd ../frontend && npm run lint && npm run check:i18n && npm audit
```

Одноразовый кластер для динамических проверок: `k3d cluster create vinaire-sec` и `examples/values-local.yaml` из
чарта; `keycloak/docker-compose.yml` даёт Keycloak для проверки мастера. Не направляйте тесты на кластер, где есть
что-то ценное: Vinaire может перезапускать, масштабировать и удалять то, что позволяет выданный ему токен.

## 7. Как сообщать о находках

Для каждой находки: маршрут или файл, шаги воспроизведения, использованная личность (какой RBAC), влияние в терминах
свойств из [security.ru.md](./security.ru.md) и, если есть, предлагаемое исправление. Принятое как остаточный риск
попадает в список «Известные остаточные риски» там же; остальное становится задачами с регрессионным тестом.
