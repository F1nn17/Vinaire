# Заметки: что поправить и доработать

Список правок по результатам ручного прохода по интерфейсу. Это не фазы ROADMAP, а
«шлифовка»; крупные пункты (метрики одной кнопкой) вынесены в ROADMAP как Phase 37.
Отмечайте сделанное, когда берёте в работу.

## Общее

- [ ] **Убрать надпись «backend: connected»** в верхней панели (`components/layout/BackendStatus.tsx`).
  Состояние бэкенда показывать только если что-то не так (например, «backend: unreachable» красным),
  а в норме — ничего.
- [ ] **Иконка вместо «треугольника».** В заголовке вкладки браузера стоит стандартная иконка Next.js
  (`app/favicon.ico`) — заменить на виноград (тот же `GrapeLogo`, что в сайдбаре): favicon + `apple-touch-icon`.
  Проверить и логотип в самой верхней панели.
- [ ] **Единое правило высоты и прокрутки.** Везде, где есть список/редактор/лог в рамке, у блока должен быть
  *собственный* скроллбар, а страница не должна прокручиваться вместе с ним и не оставлять пустоту под блоком
  (см. YAML, Logs, Revisions, ConfigMaps, Secrets ниже). Сделать один общий компонент/паттерн (flex-колонка на всю
  высоту окна, `min-h-0` + `overflow-auto` у блока) и использовать везде.

## Nodes

- [ ] **Пропала кнопка «Add node».** Причина по коду: кнопка показывается только если `canAddNode` у активного кластера
  (`app/(shell)/nodes/page.tsx:235`), а для типа `k3d` (и kind/minikube/managed) оно `false` — это решение Phase 34
  («нельзя добавить ноду на кластер, который живёт в контейнере»). Для dev-кластера k3d кнопка исчезла сознательно, но
  выглядит как пропажа. Варианты: показывать кнопку всегда, но **неактивной с пояснением** («для кластера типа k3d
  добавить ноду по SSH нельзя — используйте `k3d node create`»); дать сменить тип кластера прямо с этой страницы.

## Marketplace

- [ ] **Иконки приложений** на карточках и странице установки, чтобы приложения узнавались. Источник: поле `icon` из
  Chart.yaml/индекса репозитория. Важно с точки зрения безопасности (Phase 36): **не подгружать чужие картинки прямо в
  браузер пользователя с произвольных хостов** — CSP сейчас разрешает `img-src 'self' data: blob:`. Нужно проксировать и
  кэшировать иконки через бэкенд (только с хостов, которые уже в списке репозиториев, с лимитом размера и проверкой
  типа, отдача с `nosniff`), либо держать набор иконок рядом с `catalog.json`.
- [ ] **Убрать deprecated-чарты из каталога** (скрывать по умолчанию и не давать установить): они могут быть небезопасны.
  Возможно — переключатель «показать устаревшие» с предупреждением, выключенный по умолчанию.
- [ ] **Прогресс установки в Marketplace.** При установке приложения нужен понятный прогресс: индикатор
  (спиннер + прогресс-бар) с этапами «загрузка индекса → скачивание чарта → установка → ожидание готовности
  подов», для скачивания — **сколько скачано, сколько осталось и текущая скорость**, для установки — статус
  Helm-релиза и готовность подов (стримом, как прогресс provisioning в Phase 30). Размер чарта известен заранее
  (лимит 32 MiB, для OCI — из манифеста до загрузки), так что процент считается честно; если размера нет —
  показывать неопределённый индикатор, а не выдуманный процент. Отмена установки — кнопкой.
- [ ] **Баг: страница установки не открывается — «Couldn't load the chart: The backend is unavailable
  right now.»** (`marketplace/install/page.tsx:108`). Фронт показывает это при 502/503
  (`friendlyErrorMessage`), то есть бэкенд не смог отдать чарт. Разобраться по логам бэкенда, а не гадать:
  возможные причины — образ в кластере старый (без Phase 28/29 — маршрутов `/catalog/...` нет, 404/503), индекс
  репозитория ещё не загружен (фоновая загрузка, `searchWait`/`Warm()`) или упал, netguard блокирует адрес
  репозитория (loopback/link-local, ограничение на egress в кластере), таймаут скачивания чарта, несовпадение
  sha256 с индексом. Отдельно: сообщение «backend is unavailable» вводит в заблуждение, когда бэкенд жив, а не
  загрузился конкретный чарт — показывать реальную причину (репозиторий недоступен / нет digest / слишком большой
  чарт) и кнопку «Повторить».
