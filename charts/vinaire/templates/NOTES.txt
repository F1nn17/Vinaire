Vinaire is installing into namespace "{{ .Release.Namespace }}".

1. Wait for the pod to come up:

   kubectl rollout status deployment/{{ include "vinaire.fullname" . }} -n {{ .Release.Namespace }}

2. Reach it (adjust if you set service.type to something other than ClusterIP):

   kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "vinaire.fullname" . }} 8080:{{ .Values.service.port }}
   open http://localhost:8080

{{- if eq .Values.authMode "token" }}

3. Log in with a bounded-duration token of a ServiceAccount (or user) that
   is allowed to browse. This chart's own ServiceAccount is deliberately
   minimal — it only feeds the live-update watchers and can neither read
   Secrets nor change anything — so don't log in as it. Create one for
   yourself and bind it to the "viewer" role this chart provides:

   kubectl create serviceaccount me -n {{ .Release.Namespace }}
   kubectl create clusterrolebinding me-vinaire-viewer      --clusterrole={{ include "vinaire.fullname" . }}-viewer --serviceaccount={{ .Release.Namespace }}:me
   kubectl create token me -n {{ .Release.Namespace }} --duration=1h

   Paste that token into Vinaire's login screen. A session never outlives
   {{ .Values.sessionMaxTTL }} whatever the token's own lifetime.

   To install charts from the Marketplace (or apply YAML) the same account also needs
   the "installer" role — viewer alone only reads:

   kubectl create clusterrolebinding me-vinaire-installer  --clusterrole={{ include "vinaire.fullname" . }}-installer --serviceaccount={{ .Release.Namespace }}:me

   Changing Vinaire ITSELF — adding or removing clusters, GitOps modes and
   sources — needs one more permission. NOTE: "{{ include "vinaire.fullname" . }}-admin" is NOT cluster
   admin; it grants nothing inside Kubernetes, so it goes IN ADDITION to the
   viewer role, never instead of it:

   kubectl create clusterrolebinding me-vinaire-admin      --clusterrole={{ include "vinaire.fullname" . }}-admin --serviceaccount={{ .Release.Namespace }}:me

   A chart that creates ClusterRoles or CRDs needs rights beyond the installer
   role — Vinaire lists exactly which are missing before it starts an install.
{{- else if eq .Values.authMode "oidc" }}

3. AUTH_MODE is "oidc" — Vinaire will redirect to your configured OIDC
   provider for login. If `frontendURL` wasn't set to this install's real
   public URL, the post-login redirect may bounce somewhere unexpected —
   see the chart README and Vinaire's own Settings -> Справка -> "Вход по
   логину и паролю" for the full walkthrough and an important caveat about
   the target cluster's API server needing to trust this OIDC issuer too.
{{- else }}

3. AUTH_MODE is "disabled" — no login screen at all; every request uses
   this chart's own ServiceAccount directly. Fine for a disposable local
   cluster, not recommended for anything shared.
{{- end }}
